# Week 7 Log

Days 043 to 048. Week 1 was breadth, week 2 depth, week 3 turned the loop on itself with an audit, week 4 scaled it to a pool of people, week 5 kept what those weeks wrote, and week 6 gave the loop its first code and named its ending in public. That ending set this week's job. The last log put seven days on the record so the final entry could be read against them, which gives this log a task no earlier one had: report against a published list, item by item, then say what a repo owes its readers after the person writing it stops. Six days, six artifacts, the first executable automation in the tree, and its first image.

## What shipped, read against the promise

[The week 6 log](week-06.md) promised five things by name: the first automation that runs this repo's own handoff, a maintenance policy, a guide to lifting the loop into a real team, a field guide at the root for anyone arriving cold, and a count of what this turned out to contain. It added one conditional: if the automation did not land, the last entry would say so. Here is each, against its line.

**The automation landed, carrying four disclosed defects.** [The handoff intake](../automations/handoff-intake/README.md), an n8n workflow enforcing the packet rule from [the handoff SOP](../sops/hand-off-a-build-for-review.md), the documented path a build travels to its reviewer, takes a submitted packet, checks it server-side against what the SOP requires, opens a queue row for a complete one, and returns an incomplete one with the list of what is missing. It was built to the spec rather than the plan. The plan said write a log row and a queue row together, and [the log spec](../sops/review-log-spec.md), which defines what one row of the permanent record holds, writes the log row when the first review lands, so the workflow writes one record and leaves the log alone. Run against [the review checklist](../governance/ai-build-review-checklist.md), the gate every build here passes, the outcome was Approve with fixes, with four named failures: no dedup key, no alert on a failed write, one credential with no environment split, and no read of its own execution log. All four are written up beside the build with the fix for each, and none is fixed, a fix list shipped beside a feature list. The dedup defect is the instructive one: [the handoff ruling](../governance/what-counts-as-one-handoff.md), which decides when a returning build counts as a new arrival, makes a genuine resubmission a second arrival, so the right fix is a submission id on the form, since deduplicating on the build name would erase legitimate returns. Under this repo's own rules that counts as landing, because the disclosure rule in [the maintenance policy](../governance/maintenance-policy.md) permits an unfixed defect and forbids an unwritten one, and the conditional in last week's log never fired. Its canvas screenshot is the one image the tree holds.

**The policy landed and found a defect on the way in.** The maintenance policy defines what "complete and maintained" means from today on: three obligations, a reading rule that turns the thirty-plus living-document footers into named open work with nobody assigned, the disclosure rule with its two bounds, and three reopen conditions, each naming what it would produce. Writing the first obligation, the CI stays on, exposed that [the checks workflow](../.github/workflows/checks.yml), the CI that runs this repo's one automated check, fired only on pushes and pull requests, and a finished repo does neither, so the one control that does not depend on anyone's memory would have died the day it was needed. A weekly schedule and a manual trigger shipped the same day.

**The team guide landed.** [Lifting This Into a Real Team](../enablement/lifting-this-into-a-real-team.md), the adoption path, orders the pieces into six stages and ties each to the pain that says take it, with one exception: the spot-audit goes on a calendar, because a rubber stamp shows up as a clean record and never as pain. My draft told teams the review log has four required fields. It has five, and three separate passes caught it.

**The field guide landed, and the README points to it first.** [The field guide](../FIELD-GUIDE.md) is one page for a reader with ten minutes: the loop in five sentences and one diagram, the ten files that matter, what is real and what is synthetic, and what broke. Its evidence section concedes that of the three real catches in the tree, one was caught by a control and two by a person writing about something else. [The README](../README.md), the entry point, now puts it first in the start-here list.

**The census landed, and two of its own commands were wrong.** [The Repo by the Numbers](../analytics/the-repo-by-the-numbers.md) counts the tree: 34 living documents, 24 naming what their next pass does, 7 ever revised, and the age-cohort correction that keeps the 7 honest, since 4 of the 11 files over thirty days old have been revised against 3 of the 23 under. Every figure but one ships with the command that produces it, and running those commands is what caught the two wrong ones.

One artifact shipped that the list never promised. [How This Repo Is Made](../docs/how-this-repo-is-made.md), the method note, discloses how this text gets produced: nearly every sentence drafted by a model, with the subjects, briefs, verification, and the decision to ship all mine. Drafting it turned up the week's longest-lived defect. The log spec said "four required fields" in one line while its own field list said five, and the line stood for seventeen days across two version bumps in the file the review side reads most often. It is corrected, and the spec is at v4. No control in this repo could have caught it, because no check here reads prose for internal contradiction.

## What I actually learned

**Finishing is itself a test.** Every closing document this week found a real defect, in the thing it was closing or in its own draft. The policy found the CI trigger gap. The method note found the seventeen-day stale count. The census draft carried two wrong commands, caught by running them. The field guide draft carried a sentence saying the standards had been "used," one word claiming operational history nobody has, caught by a pass arranged to read the draft cold with no access to the tree. The mechanisms differ, forced claims for the first two, execution for the third, arranged review for the fourth, but each document forced claims narrow enough to check, and a claim narrow enough to check is a claim that gets checked. This is the week's version of week 6's finding that an arrow has to pick a node. A closing document has to say what the thing is, and saying it is what turns every soft spot hard.

**The controls caught less than the writing did.** Within the week, the one control that fired at defects was the checklist run against the automation, and its four findings are build defects a checklist is built to find. Every defect in prose fell to a person, and none to [the index check](../checks/check_index.py), the first code this tree carried, which ran green all week; its four mechanical rules read one index and nothing else. The field guide's all-time tally says the same thing over the whole run: three real catches, one by a control, two by a person writing about something else. The honest implication is that the checks here are narrow, while the broadest check this repo ever had was the standing obligation to describe itself exactly, every day, in a place where every claim is checkable. That obligation ends today, and that is why the policy takes the shape it does: the scheduled run replaces the push nobody will make, and the reopen conditions replace the agenda the cadence used to generate.

**Turning outward changed what the repo was.** Weeks 1 through 6 wrote a system for people inside the loop, every file assuming a builder, a reviewer, or a keeper already at their station. Week 7 wrote for people outside it: an automation a stranger can import, a policy a stranger can hold this repo to, an adoption path, a disclosure of method, a census a stranger can recompute, a front door. The test of week 7 is whether a stranger can now tell what they are holding, and every artifact this week answers some version of that question.

## What was thinner than I wanted

The eval set named by [the evals memo](../analytics/evals-and-the-review-loop.md), the ruling on what a saved graded set can gate, still does not exist. The routing line that [the placement guide](../enablement/where-a-human-stays-in-the-loop.md), the design-time ruling on where a person sits beside a model step, deferred is still deferred, because the memo says only such a set can supply it.

The checklist edits that the placement guide and [the change standard](../standards/prompt-and-model-change-control.md), the procedure a prompt or model change goes through, both name have still not landed, and the checklist still asks its stakes question in the old words.

And the standing one, unchanged since week 3 and permanent as of today: nothing here ever ran with a real team. No queue anyone pulled from, no build handed to a second person, no audit by a third. The repo ends with that gap open, and the policy makes closing it the first reopen condition, the only one that yields evidence a person sitting alone cannot write.

## What happens now

Today the last entry ships, the front page takes its terminal line, the tree gets tagged v1.0.0, and a release points at the field guide. After that the maintenance policy governs. The check runs weekly whether or not anyone touches the repo, a red run gets fixed, a factual error gets corrected and bumps a version, a defect found and left alone gets written into the file that owns it, and the named passes stay named with nobody assigned. That list describes stewardship, which is what a finished thing gets in place of a roadmap.

The streak is at forty-eight days. Week 5 set a test, whether the repo still generated its own agenda, and the two logs since have run it. This week the repo passed one last time in the only way left: the agenda came from the act of finishing, the one source that cannot recur. A cadence that ends on a chosen day turns this record into a fixed thing somebody else can check, every claim against a dated file. That is what stopping buys.
