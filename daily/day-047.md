# Day 047: Thirty-four living documents, seven revisions

**Fri 2026-08-07 · Analyze · Day 47 of 49**

This repo has spent seven weeks arguing that a number is only worth having if you can say exactly what
it counts. It had never counted itself. Today it did, and the first honest result is unflattering:
thirty-four files here end by calling themselves living documents, twenty-four of those name what their
next pass will do, and seven have ever been revised.

across the first thirty-six daily entries and thirty-seven after it.

## What I learned

The headline number was wrong the first time, and the way it was wrong is the useful part. Thirty-four
living documents against seven revisions is a comparison with no control in it. This repo added roughly
a file a day, so the pile of never-revised files is stuffed with files too young to have been revised.
Eight of them are under ten days old. One is a day old.

Splitting by the date each file was added gives the honest version. Of the files older than thirty
days, four of eleven were revised. Of the newer ones, three of twenty-three. The median revised file is
forty-two days old and the median unrevised one is eighteen. The neglect is real, and it is smaller
than the raw ratio makes it look. That is the difference between a number that indicts and a number
that informs, and only one of them was worth publishing.

What survives the correction is a pattern about which files moved. The seven are the standard, the
checklist, both SOPs, both records, and the check's notes: the pieces somebody actually follows or gets
judged against. The obvious explanation is exposure, and it does not hold, because the tool-adoption
guide is the second-oldest artifact here and a guide people follow, and it never left v1. So did the
builder self-check, at thirty-seven days. Old and followed was not enough. Old and argued with was.

Two of the commands I published did not produce the numbers beside them. One counted lines containing a
link rather than links, which reads the same until a line has two. The other described its own output
wrongly. Both were caught by running them, which is the only test that means anything for a file whose
entire premise is that a reader can recompute it.
