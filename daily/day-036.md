# Day 036 - Build

**Date:** 2026-07-27
**Pillar:** Build

## Tidbit

Thirty-five days of writing produced a repo that had never run anything, and the gap I kept naming in every
weekly log was the same one: a specified check catches exactly as much as no check. Today it ran, and the
first run earned the difference. It found the two files Day 033's memo and Day 034's map had each predicted
by name, plus the tally drift that followed from them, which is the useful outcome because a check that
passes on its first run tells you nothing about whether it works. So I did the other half too and broke
things on purpose: a bad path, a wrong version, a false count, each one caught and named. A check nobody has
seen fail is a check nobody should trust. The thing I did not expect was how much the writing had already
done. Day 033 specified four rules carefully enough that implementing them was transcription, and the one
place I had to think was a scope decision the memo had already flagged as the soft edge. Specifying well is
most of building, when the specification was written honestly enough to be followed.

## Shipped

`checks/check_index.py`, the first executable thing in this repo. Python 3, standard library only, run with
`python checks/check_index.py` from the repo root, exit 0 when the four rules pass and 1 when any fail, with
the offending file names printed. It implements the check Day 033 specified: every cited path resolves,
every entry's title and version match the target file's H1, every in-scope file is indexed or excluded on
purpose, and the opening tally recomputes off the tree. The first run failed two of four rules and named
`analytics/measure-or-test.md` and `integration/week-05-the-loop-gets-kept.md`, the two files predicted in
advance, along with a tally that had drifted to seventeen pieces and three maps when the tree held eighteen
and four. Fixing `sops/the-review-loop-in-order.md` took both entries and the corrected count, and the
re-run passed all four. Three negative tests confirmed it fails when it should. Also `checks/README.md` for
how to run it and what it cannot see, and a `checks/` row in the README layout.
