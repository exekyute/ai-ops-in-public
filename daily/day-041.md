# Day 041: A second entrance to the same gate

**Sat 2026-08-01 · Integrate · Day 41 of 49**

This week put four AI-specific pieces into a review system that was designed before any of them
existed, one a day, each answering the day in front of it. Laid end to end they raise a question none
of them answers alone: does a step that calls a model need its own loop running alongside the old one,
or does it fit inside the loop already here? Drawing it settled the question.

## Shipped

[integration/week-06-the-loop-meets-the-model.md](../integration/week-06-the-loop-meets-the-model.md),
the sixth weekly map, carrying the repo's second diagram. It puts this week's five pieces in order: run
the rule that was only written down, take the running off memory, decide where the person sits before

The diagram is the day's real output. It draws the loop's spine, then everything a model step hangs
underneath it: output, the person the placement put there, the labeled cases that person produces, and
the eval set those cases feed. The answer to the question above turned out to be no second loop. A
prompt or model change rejoins the build path at the builder self-check, carries its eval result into
the same handoff packet, and reaches the same reviewer working the same checklist. One gate, two
entrances. It went into [the review-loop index](../sops/the-review-loop-in-order.md), the start-here
page ordering every piece of the review system, taking it to five weekly maps.

## What I learned

The diagram caught an error the prose had been hiding. My first version ran the arrow from the eval
straight to the handoff packet, which reads plausibly and is wrong.
[The change-control standard](../standards/prompt-and-model-change-control.md), written two days
earlier, says a configuration change preps against
[the builder self-check](../enablement/builder-self-check.md) and carries the eval result as evidence
inside the packet. So the arrow had to land one step earlier, on the self-check. In prose that mistake
would have survived indefinitely, because a sentence can say a change "goes through review" and stay
true enough to pass. An arrow has to pick a node.

That is the case for drawing a system you have already described five times. Prose tolerates a vague
join. A diagram makes you commit to which box the line touches, and the commitment is where you find
out whether you actually knew.

The other thing worth recording is what the week's agenda was made of. Last week the work came from
using a spec until it broke. This week it came from the repo's own written limits coming due: one piece
answered a limit a footer had confessed, two answered limits this same week opened days apart, and two
closed gaps that had been sitting inside shipped rules for weeks with nobody writing them down. A repo
that records its limits is building a backlog it can see. A repo that writes rules with no enforcer is
building one it cannot.
