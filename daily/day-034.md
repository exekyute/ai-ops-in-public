# Day 034 - Integrate

**Date:** 2026-07-25
**Pillar:** Integrate

## Tidbit

Laying week 5 out in order showed a week I did not plan. Weeks 2 through 4 each added a piece somebody
decided the loop still needed, and this week every day answered a problem the day before had created:
filling the records exposed a conflict, the conflict wanted a ruling, the ruling wanted somewhere a person
would meet it, and the pile that produced wanted a way in. That is what upkeep turns out to be, work the
system hands you rather than work picked off a roadmap. The sharper half is where those problems came from.
Every one was found by use and none by review. The handoff conflict sat in two files for four days, through
a weekly map and a reflect, and twelve invented rows surfaced it in an afternoon. A spec is only tested by
being used, and the cheapest use is filling it in with fake data. That cuts back at me too, since I wrote
the rows and the specs both, so the use was sympathetic and a real user would find more.

## Shipped

`integration/week-05-the-loop-gets-kept.md` (v1): week 5's five pieces mapped as one loop, the first week
this repo maintained something instead of adding to it. Five stages, each pointing to its piece: fill the
record (the populated log and queue, where use tests the spec), settle what the use exposed (the handoff
ruling), put the decision where a person meets it (the write-time log-keeper guide), make the grown set
findable (the index), and decide how the upkeep gets checked (the measure-or-test memo), which runs at the
moment of change and so points back inside every stage before it. The seams section found the thing I had
not seen: this loop closes differently from every prior week. Weeks 2, 3, and 4 each ended in a number
pointing back at one earlier stage, and this one ends in a check whose trigger is the act of changing
anything, so the feedback runs through editing rather than through measuring, which is what a maintenance
loop looks like. The honest gaps it names: the records are authored by the same person who wrote the specs,
the check is specified and has never been run, the loop still has not run with real people, and five weekly
maps now sit in `integration/` with nothing indexing them, which makes this map the second unindexed file
in the tree, after the memo that named the rule that would flag it.
