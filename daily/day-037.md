# Day 037: A rule nobody enforces is a suggestion

**Tue 2026-07-28 · Govern · Day 37 of 49**

Yesterday this repo got its first working code: a script that checks whether the repo's own index page
is telling the truth about the files around it. It caught real drift on its first run. Running it still
depended on somebody remembering to type a command, and a check that waits on memory is the exact
failure this repo keeps writing about. Today the repo runs it itself.

## Shipped

[.github/workflows/checks.yml](../.github/workflows/checks.yml): a GitHub Actions workflow that runs
[check_index.py](../checks/check_index.py), the script that verifies the
[review-loop index](../sops/the-review-loop-in-order.md) (the start-here page ordering every piece of
the review system) against the files it points at. It runs on every push and pull request, and a
failing check now fails the build where anyone can see it. [checks/README.md](../checks/README.md) went
to v2: the "nothing runs it automatically" limit is deleted because it stopped being true, one day
after it was written, and the wiring is recorded in its place.

## What I learned

The question queued for today was whether an unenforced expectation is worth writing into the
[automation standard](../standards/automation-standards.md), the baseline every build here is judged
against. Sitting down to answer it, the question dissolved. Writing "run the check" into a document
would have produced one more described control, in a repo that has already warned twice that a
specified check nobody runs catches exactly as much as no check. The enforcement itself cost sixteen
lines of YAML, which is less than the paragraph arguing for the rule would have cost. That is the
governance lesson worth keeping: before writing a rule, price its enforcement. When the enforcement is
cheaper than the rule, ship the enforcement and let the rule be one line that points at it.

## Next

The check now runs without a person. Everything it verifies, though, is generic to any repo of
documents: paths, versions, counts. Nothing here yet governs the part that is specific to AI systems,
which is output that is right most of the time and wrong without warning. The next few days take the
review loop into that territory, starting with how to decide, in advance, where a person has to look
at what a model produced.
